# 知乎盐选单章正文结构槽模板设计

## 目标

提供一个可直接加载和运行的 `zhihu-salt-chapter-draft` 结构槽模板，用于验证结构槽引擎在真实知乎短故事章节生产中的基础价值。

本模板只负责承载和生成一章最终正文，不把大纲、章节执行包、审核账本和全文总控混入同一棵槽树。七轮写作流程、章节知识边界和质量判断由模板绑定的 Skill 与后续审核模板负责；本模板负责把章节正文表达为受约束的结构化槽树，并输出稳定的 Markdown 文件。

## 输入

- 当前章节执行包：正文 Agent 可使用的最小、无剧透章节上下文。
- 上一版正文：可选，仅用于按返修单修订。
- 安全返修单：可选，限制本次可修改范围。

## 运行链

```text
structure → fill → seal → submitter
```

- `structure`：读取章节执行包，创建章节槽树，并决定 `scene_block` 的数量、顺序和类型。
- `fill`：按槽位类型填写标题、开场、场景、情绪余波和章尾内容；只能在活动草稿上写作。
- `seal`：对已填写槽树执行必填项、顺序、内容类型、篇章边界和 Markdown 组装前校验。校验失败时向 `fill` 发出返修消息。
- `submitter`：只接收已 Seal 的产物，提交最终章节 Markdown。

## 槽位合同

根槽 `chapter` 的子槽固定为：

1. `title`：必填、短标题字符串。
2. `opening`：必填、章节开场与最短承接正文。
3. `scene_block`：可重复的场景功能单元，至少一个，最多 16 个；每个场景正文必须是非空字符串。
4. `emotional_closure`：必填、情绪或关系余波；没有额外余波时仍由模板明确承载章节收束语义。
5. `chapter_end`：必填、本章状态和阅读动力落点。

槽位树的顺序就是最终 Markdown 的顺序。模板不规定一章必须包含某种题材、冲突、反转或固定情绪强度；这些属于输入执行包和 Skill 的业务约束。

## 输出合同

Assembler 生成一个文件：`chapter.md`。输出顺序为：

```markdown
# {title}

{opening}

{scene_block_1}

...

{emotional_closure}

{chapter_end}
```

输出只能来源于已 Seal 的槽树，不读取原始输入或未 Seal 草稿。

## 验证边界

模板级 validator 只验证机器可判定的结构约束：

- 根槽和子槽类型正确；
- 必填槽存在且内容非空；
- `scene_block` 数量在 1–16 之间；
- 槽位顺序不变；
- 内容长度不超过模板声明的限制；
- 输出路径和 assembler route 与合同一致。

知乎故事的因果、人物、情绪、泄漏和文风质量不在本模板中伪装成简单字符串规则；它们由章节 Skill、独立审核模板和总控负责。

## 不在本模板范围内

- 完整故事大纲与私有蓝图；
- 无剧透章节执行包的编译；
- 章节审核报告、证据 sidecar 和状态账本；
- 全文组装、全文连续性审计与最终交付证书；
- Notion/块状编辑器界面。

这些能力后续作为独立模板复用本模板的产物。

## 验收标准

1. 模板在结构槽 runtime enabled 环境下可以被加载。
2. `structure → fill → seal → submitter` 路由通过模板图和阶段校验。
3. 缺少标题、开场、场景、余波或章尾时 Seal fail closed。
4. 场景数量、槽类型或顺序非法时 Seal fail closed。
5. 合法槽树可以确定性组装为 `chapter.md`。
6. 最终文件不包含模板控制字段、未 Seal 草稿或原始输入。
7. 现有 basic 模板和九个 ForgeAction 不受影响。
