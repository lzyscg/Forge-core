# 分章执行包协议

自动化生产、参考文本边界映射和正式产物写入还必须遵守 [structured-controller.md](structured-controller.md)。控制器只信任通过 schema 与 Markdown 交叉检查的 sidecar，不信任退出码、文件存在或自然语言结论。

编译每一章前必须同时加载两份彼此隔离的上游输入：只含本章知识的私有蓝图区段，以及初始化阶段冻结的公开稳定契约。后者只含人称、视角、叙述时点、现实层级、声音、语言呼吸、标题承诺和当前可公开身份，不得含未来答案。只截取章节区段而漏传稳定契约属于输入不完整，必须停止；不得把上一章账本当成稳定契约的替代品。

## 执行包模板

没有内容的字段直接删掉，不用填“无”。正文可见包只保留直接影响本章写作的内容；完整事实核验与攻击检查留在私有审核层。

```markdown
# 第 N 章正文执行包

## 输出与章首
- 标题形式与目标汉字数：只在此处保留一个机器可读预算，使用阿拉伯数字 `下限–上限 汉字`。
- 人称、视角范围、叙述时点：
- 当前时间、地点与在场人物：
- 当前动作真正需要的最短承接：
- 本章会被自然叫出的公开姓名、代词与关系：

## 本章唯一任务
- 主要阅读动力：
- 本章结束时必须造成的变化：

## 场景功能单元
按正文必要先后排列；每当行动、关系、信息或读者压力发生一次不可忽略的变化，结束当前单元。

### U1：[当前世界中的简短场景标识]
- 变化：[起始状态] → [单元结束后的新状态]
- 写作链：[触发] → [必须回应] → [反馈 / 反作用]
- 压力：[压力、误解或预期怎样变化；直接压进本单元]
- 直接写出：[不可摘要的对白、动作或信息；所需硬事实以自然世界事实在此出现]
- 留白：[只用肯定句写正文停在哪个已知结果；未来答案、物件和机制的具体反例留在私有审核层]
- 本单元正向有限清单：人物：[已注册且本单元可出现的人]；在场对象：[对象@位置@可见/可触达状态]；可用事实：[可以被叙述引用、但不等于当前现场可见的既有事实]
- 授权容量载体：对白轮次 [N]；动作反馈闭环 [N]；认知或感知转折 [N]；事后反应 [N]
- 保真：H-...
- 展开：细写 / 标准 / 轻过渡

## 声音与正文边界
- 叙述者判断与人物话语身份：
- 句式、段落与留白呼吸：
- 可局部创造：只允许能改变当前动作、关系、信息判断、读者压力或声音，且在当前场景内闭合的细节。
- 正向有限清单：当前可调用的具体对象与事实只有……

## 章尾状态
- 结束动作、决定或关系变化：
- 允许留给读者的表层问题：
- 当前知识停点：[只写已经成立到哪一步，不列举后续禁写事件]

只输出本章标题和正文，不解释执行包，不预告后文。
```

“输出与章首”中的人称、视角、叙述时点以及公开姓名、代词与关系必须能逐项追溯到公开稳定契约。章节区段没有重复写这些信息时仍以稳定契约为准；章节区段若明确冲突则退回上游，不允许模型任选其一。

所有写作链必须是已经编译完成的单一路径，不得用“或者、也可以、由正文决定”保留分支。按单元顺序复核人物、物件与界面状态：已经倒扣的手机、关闭的页面、交出的文件或离场的人物，后续若再次使用必须先有可见恢复动作；章尾状态动作放在最后一次使用之后。

编译器原始输出可以引用私有硬事实 ID；控制器交付正文前按首次出现顺序将其确定性改名为 `H-01`、`H-02`……。正文可见 Markdown 不保留多字母内部分类前缀。

数值预算只在“输出与章首”保留一次，并固定写成阿拉伯数字 `下限–上限 汉字`，便于运行器读取交付下限。情绪和读者压力压入相应场景卡，不再另设重复字段。目标篇幅必须由实际授权的场景卡反推；删除、后移或不再授权内容时同步降低预算，不能让正文模型自由填充。私有蓝图即使给出精确句数、段数或平均段长，编译时也必须翻译为“短段为主、关键动作单独落段”等定性呼吸，不得原样进入正文可见包。

容量载体行只存在于编译器原始输出，`accept-result --controller-owned-packet-sidecar` 验收后必须写入私有 sidecar 并从正文可见 Markdown 剥离。它是语义计数，不是箭头或句子计数。问答双方分别算一个对白轮次；动作必须得到可见反馈并改变下一反应才算闭环；新证据只有改变人物判断才算认知或感知转折；主变化完成后的短暂消化、关系回声或决定加固才算事后反应。重复解释、静态物件枚举、普通移动、程序步骤和同一结论的改写不计。单元硬上限依次为 `8 / 4 / 4 / 2`，超过时拆分或去重。控制器以载体加权得到原始容量，再用原始容量的 `4/5` 约束可设置的硬下限、`11/10` 约束可保留的范围上限；两道门任一失败就退回编译，不把错误预算交给正文模型。正常生产建议把硬下限放在原始容量的约 65%–75%，`4/5` 只是不可超过的安全上界。若两个完整兑现的独立稿都低于下限，而过线稿依赖重复动作或同义总结，退回预算下调下限，不要求正文补字。

同一章含两个以上时间、地点或独立场景时，不得只给全章对象总表。每个 U 单元必须有自己的“本单元正向有限清单”；尚未进入该单元的后段人物、物件、称呼和结论不能提前列入。清单必须区分“人物”“在场对象”和“可用事实”：一个对象只作为既有事实被提及时，不能出现在“在场对象”中，也不能让正文人物看见、触碰或移动它。全章清单只保存跨单元持续存在的共享状态，不能替代单元清单。

## 私有审核层

私有审核层供控制器编译、验收和生成 sidecar，绝不附给正文模型。它至少保留：

- 边界 ID、源文本范围、边界签名、上一不可跨越文本和下一禁止文本；
- 完整 H 事实语义等价表：实体、数量与范围、肯否与确定性、方向、时点、因果；
- 禁止弱化、加强、改向或把未知写成已知的检查；
- 每项 H 事实到唯一场景卡的映射，确保事实只在一个可写位置自然出现；
- 针对未来泄露、凭空补机制、错误合并场景和元话语照抄的攻击检查；
- 正文模型最可能乱补的具体物件、数字、来源、机制和未来答案；这些攻击词不得反向出现在正文可见包；
- 完整场景覆盖矩阵、章尾连续性与审核结论。

```markdown
- 当前地点：
- 在场/可访问人物：

## 普通已成立事实

## 知识状态

## 跨章未完成义务
- O-...：类型 / 必须维持或完成的表层义务 / 建立章 / 最近确认章 / 正文证据。

## 待回收信号

- 原分区与 ID / completed、invalidated 或 paid_off / 本章可见结算事件 / 正文证据。

## 下一章承接
- 最后可见动作或话语：
- 必须连续的状态：
```

Markdown 供人读，`ledger-state.schema.json` sidecar 供程序比对。活跃 ID 不得跨分区移动；上一版活跃状态、义务或信号若未在当前版保留，必须在当前章闭合项中留下同 ID、闭合类型、可见事件和证据，否则控制器拒绝更新。

## 编译检查

交付执行包前，从正文模型视角做一次攻击性阅读：

1. 只看这个包，能否推断出本章之后才揭示的具体答案？
2. 某条“禁止事项”是否反而说出了秘密的名称？
3. 是否夹带完整故事梗概、完整人物弧或完整反转顺序？
4. 是否把未来计划误写成章首已成立事实？
5. 是否缺少当前场景必需的主语、对象、位置、知识来源或动作结果？
6. 是否为了“给模型自由”留下了会改变全局的事实空洞？
7. 若正文模型沿用本包对主角的称谓，是否会违反目标人称？
8. 本章硬事实是否在数量、范围、极性、方向、时点或确定性上被软化、加强或反转？
9. 本章是否存在点名、报道、文件或身份核验场景，却没有提供必要的公开姓名与称呼？
10. 本章是否触发回忆或跨时间对照，却没有列明可调用的既有事件、人物存亡顺序和物件来源？
11. 包内的“硬事实、冻结、功能、任务、保持连续、同义煽情”等控制措辞，是否容易被模型原样写进正文？
12. 上章仍在场或明确外出的角色，本章是否直接消失或返场，却没有最短离场 / 返场桥？
13. 每个细写或标准单元是否具备触发、回应、反馈和状态变化；是否把“节点出现”误当成“场景完成”？
14. 某个细节是否只能以“有画面、有氛围、更生动”解释，而删除后不改变动作、关系、判断、压力、声音或方位？
15. 同一主题若重复出现，是否每次改变了对象、强度、证据、关系、风险或不可逆后果？
16. 承担情绪任务的单元是否只写了事实变化，没有规定压力如何外化并改变下一反应？
17. 可写内容里是否混入“方向不能写反、必须保留、不可弱化、不得新增”等可能被角色直接复述的审核命令？
18. 当前单元是否存在模型为了连贯最可能擅自补出的发现方式、精确时长、传播渠道、证据来源或机制，却没有列入“保持不具体”？
19. 执行包是否把编译端完整分析表原样交给正文模型，而没有压缩为短执行卡？
20. 本章授权内容已经减少或后移，篇幅预算是否仍机械继承参考文本旧长度？
21. 带对象的动作是否缺主语、缺对象或用途不明；同一物件是否未经移动就换了位置，替换物与旧物的安装、拆除或交接顺序是否矛盾？
22. 正文是否把“没听见、没看见、暂时无法确认”升级成“没有人、没有危险、幕后目的确定”？
23. 有参考原文时，当前章节的边界 ID、原标签、源范围、首尾锚点、最后不可越过文本和下一章禁止提前出现文本是否与 `chapter-boundaries.json` 完全一致？
24. 自动化输出是否同时具有对应操作的 JSON sidecar，且章节签名、verdict、缺失单元、越界事实和返修范围与 Markdown 一致？
25. 私有蓝图是否把上一账本中仍为计划、在途或未完成的义务直接升级为章首已完成事实，且没有当前章可见交接链？
26. 本章所谓“新打击”是否只是把上一账本已经成立的解约、延期、声明、损失或关系终止重新播放一遍？
27. 正文可见包是否出现大于当前章序号的 `Bxxx`、未来章节说明或后续答案？
28. 未署名发送者是否被确认成某人，或个人账号、非官方、初步结果是否被升级为正式、最终或已证实结论？
27. 集合对象的总量、当前位置与保管者是否能同时成立，是否把逻辑证据链、同屏或同目录误当成物理共址？
28. 当前动作是否借用了已暂停、撤销或冻结的机构、账号、职位或身份权限？

前四项任一为是：删去或改为纯表象。
第五、六项任一为是：补充当前章所需事实，但不补后文解释。
第七项为是：把状态、节点、情绪和章尾字段全部改成目标人称；不只修改顶部契约。
第八项为是：回到私有硬事实保真表逐项改正，不能用近义概括替代精确语义。
第九项为是：补入最小公开身份名册；只补当前已经公开的姓名、代词与关系，不补秘密身份。
第十项为是：补入最小历史连续性边界；不允许正文模型用新回忆、新物件或已死亡人物填补情绪。
第十一项为是：把控制措辞改成角色世界中的自然表达，或在输出要求中明确禁止照抄；审核时将元话语泄露列为硬错误。
第十二项为是：把角色最后位置和本章首次位置写入执行包，并要求在首次出现前补最短动作或时间桥；不能靠章节切换默认瞬移。
第十三项为否：补齐单元完成条件；轻过渡可以简化，但必须有明确状态桥。
第十四项为是：删除该细节或写清它实际改变的当前功能；“不影响后文”不是保留理由。
第十五项为否：合并同义重复；若必须重复，加上新的对象、强度、证据、关系、风险或后果。
第十六项为是：补写该单元的情绪 / 读者压力变化及允许载体；程序和轻过渡没有情绪任务时不补。
第十七项为是：把可写内容改成角色世界里的自然肯定事实，把命令留在保真核对字段。
第十八项为是：正文可见包只用肯定句说明正文停留在哪个已知结果，或给正向有限对象清单；具体禁写物、机制和未来答案移入私有攻击检查，避免负面提示反向诱发。
第十九项为是：保留总控端完整分析，正文包改用“变化、写作链、压力、直接写出、留白、保真、展开”短卡；删除重复字段。
第二十项为是：按实际执行卡重新估算范围；不能靠恢复未授权内容或装饰句达到旧字数。
第二十一项为是：按“主体—动作—对象—原位置—移动—新位置”恢复最小连续链；用途不明的动作直接删除，不用新设定解释。
第二十二项为是：把结论退回感官证据实际支持的确定性；只写当下可见、可听或可合理推断的范围，不补答案。
第二十三项为否：停止编译，重新机械切片；不得靠自然语言猜测或人工正规化标签继续。
第二十四项为否：产物判为结构无效，保存原始失败输出但不覆盖正式文件，也不进入下一阶段。
第二十五项为是：以已通过账本为准；把完成动作编译进当前章可见单元，或退回私有蓝图，不得用完成时态倒灌。
第二十六项为是：删除重演；只有出现新的对象、强度、证据、风险或不可逆后果时才保留为后续事件。
第二十七项为否：按“总量—原持有者—交接动作—当前持有者”重建库存；数字文件、逻辑关联和物理容器分别登记。
第二十八项为是：若无恢复授权，改用仍具权限的个人主体或停止该动作，不得靠机构名称暗示权限仍在。

## 审核报告模板

```markdown
# 第 N 章审核

结论：通过 / 返修

## 场景单元完成矩阵
| 单元 | 变化 | 写作链 | 压力 | 直接写出 | 留白 / 保真 | 证据与缺口 |
|---|---|---|---|---|---|---|
| U1 | 完成 / 缺失 / 改写 / 越界 | ... | ... | ... | ... | 引用最短正文证据 |

## 段落功能归属
| 定位短句 | 归属 | 判定 | 理由 |
|---|---|---|---|
| “……” | U1 / H-A / 压力 / 声音 / 状态桥 / 无 | 保留 / 删除 / 替换 | 删除后具体改变什么，或为什么什么都不改变 |

自动化证据不得只复述上述结论。`draft-audit-evidence.schema.json` 必须逐单元给出触发、回应、反馈和新状态的正文原句，逐段给出文本哈希、功能所有者、具体作用和保留判定，并在 `authorization_findings` 中登记疑似新增的身份、物件、地点 / 路线、时间 / 数字、外貌 / 动作、前史 / 习惯、原因 / 动机、知识结论和连续状态。每个登记项必须引用正文真实子串；判为 `authorized` 时必须填写场景卡、正向有限清单、H ID、章首状态或账本来源，不能用“符合常识”代替来源。控制器会复算正文哈希、汉字数、段落数量、段落哈希和证据子串；`--require-pass` 下仍有缺失单元、无功能段、待修段或未解决授权项即拒绝。

审核时把对白声明、名词修饰语和位置介词还原为它们建立的事实。对话“可以调阅、我把数据带来了”分别建立访问机制和持有状态，不能只引用角色身份或“允许衔接对白”放行；“厂方下发的话术”比“留存的话术”多出来源与传播动作；“同一证据链”只授权逻辑关联，不授权同一袋、容器、文件夹或目录。集合对象还要核对总量、交出数量与当前持有者，不能让同一份对象同时留在原容器和外部机构。机构名义、账号或职位修饰语会建立行动权限；账本已暂停、撤销或冻结时，除非执行包先授权恢复，否则不得判为可用主体。只有执行包明确给出这些机制、来源、介质、共址关系和权限时才能判为 `authorized`。

单元正向有限清单按闭集审核：登记门不等于登记钥匙、门卡、门把部件、走廊或前室；登记概述动作不等于登记实施工具与步骤。带中文引号写在“直接写出”中的锁定台词必须在正文逐字存在，字段明确写“语义等值”时才允许改写。当前拒绝、未知和尚未开始不得升级成永久状态。`complete` 单元若仍附带 `repair_instruction`，审核结论内部矛盾，控制器必须拒绝。

## 账本增量交接

账本模型不得自由重写上一章状态。输入包括上一账本 JSON、当前通过稿、通过审核证据和控制器句子 ID view；输出只包含：

- 当前时空、人物可访问性、叙述者知识、判断、悬置问题和下一章连续性；每项绑定当前句子 ID 或上一账本稳定 ID；
- 当前章新成立的普通事实、活跃状态、义务与信号；每项绑定当前句子 ID；
- 上一账本每个活跃 ID 的唯一操作：原样继承、用当前句复核、用当前句修订，或用当前句闭合。

控制器负责复制普通旧事实和旧闭合项、保留 carry 项原文、回填精确证据、更新最近确认章、生成闭合记录、校验 ID 和渲染给下一章使用的 Markdown。声音锚点只让模型选择一个正文句子 ID，控制器必须用该 ID 对应的完整原句覆盖模型文本，连同标点一起冻结；不得为补一个标点重跑全量语义 JSON。模型未逐项处理上一章活跃 ID，或试图用 carry 携带改写字段时，账本整体拒绝。

账本不得提高身份和证据确定性：未署名发送者只进入未知信号，人物联想进入叙述者推断；个人账号、非官方或初步结果保留限定词。正文未明确具体时间、地点时使用标准未知回退，不从屏幕、手机、相对快慢或“已经”推断时空。证据只支持暂停时，不得补写“观察期未结束”等更强负面状态。

账本返修单首部必须包含唯一的机器权限声明，例如 `<!-- allowed-json-paths: ["$.context.current_time", "$.new_facts[id=F-B005-02].text"] -->`。控制器按稳定 ID 归一化含 ID 数组的差异，未列路径的顺手修正也拒绝。返修模型输出先通过 `validate-ledger-repair-scope`，再进入语义接收和前后迁移门禁。
```
