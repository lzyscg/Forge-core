# 盐选短篇分章执行包

## 核心职责

本 Skill 是大纲端与正文端之间的隔离层。它可以读取完整大纲和已验收正文；正文模型不得读取这些材料，只接收本 Skill 产出的单章执行包。

执行包追求“充分但最小”：

- 足以完整写出当前章节；
- 不包含当前章节尚不该知道的后文事实、解释和答案；
- 不把完整大纲换一种格式重新塞给正文模型；
- 只继承已被验收正文真正建立的跨章状态。

需要逐章写作时，先读 [references/packet-protocol.md](references/packet-protocol.md)。有参考原文、自动化控制器或需要把结果写入正式生产目录时，还必须读 [references/structured-controller.md](references/structured-controller.md)，并使用 `scripts/controller_artifact.py` 做 fail-closed 验证。

## 四种操作

开始前只选择一种操作，不在一次输出中混做：

- 有完整大纲、私有蓝图或用户要求建立全局约束，且没有待审正文：执行 A 初始化；
- 有目标章节、私有蓝图、公开稳定契约和上一版账本，用户要求生成当前章输入：执行 B 编译；
- 有当前章节执行包与待审正文：执行 C 审核章节；`SKILL.md` 和协议只作为指令，不评论其架构、路径、安装或写法；
- 有已通过正文与旧账本，用户要求滚动状态：执行 D 更新账本。

输入同时满足多种操作时，以用户明确指定的操作为准；用户没有指定且会改变输出类型时，只指出缺少哪一种选择，不自行混合。审核任务只输出审核报告，编译任务只输出执行包，更新任务只输出账本。

## Agent 分步编译合同

本 Skill 的“编译”不是一次把完整蓝图翻译成执行包。它必须生成下列可追踪中间产物；自动化运行分别存档并由总控接受，普通交互只展示最终执行包，但仍按相同顺序完成。

1. **章节重点简报** → `chapter-focus-brief.md`：本章唯一核心目的、全部 P0 的不可替代发生方式、章首/章尾状态、公开知识停点与硬事实别名映射。它只回答“本章必须让什么真正发生”。
2. **场景功能计划** → `chapter-scene-plan.md`：将每个 P0 放入有先后关系的场景单元，写明触发、必须回应、反馈、新状态、必要压力与正向有限清单。P0 的人物、渠道、对象或结果若在此被换成近似桥段，计划不得通过。
3. **计划门禁** → `chapter-plan-gate.json`：控制器核对 P0 全覆盖、发生方式、硬事实、知识停点、章尾和跨章状态。计划未通过不得生成正文可见包；不能让正文模型自行补齐遗漏。
4. **正文执行包** → `chapter-packet.md`：只从已通过的计划压缩出正文模型所需的最小信息。正文可见包不携带私有审核表、未来答案或攻击样例。
5. **packet 门禁** → 现有 packet sidecar：校验结构、容量、身份、边界和泄露后，才允许交给正文节点。

返工路由固定为：重点遗漏/发生方式错误回第 1 步；因果或场景承接错误回第 2 步；计划已正确而压缩时丢失信息回第 4 步；格式、容量或泄露错误回第 5 步。不得直接让正文草稿承担编译返工。

### A. 初始化

输入：完整大纲、用户硬要求、可选参考风格分析。

有参考原文时，私有蓝图之前必须先存在通过 schema 的 `chapter-boundaries.json`。它由源文件机械提取，保存原标签、源哈希、标题与正文范围、首尾锚点、本章最后不可越过文本和下一章禁止提前出现文本。不得让大纲模型自行合并、补号、正规化或重新判断源章节边界。边界 map 与源文件不一致时停止初始化，不生成可进入生产链的蓝图。

建立两个互不混用的内部区域：

1. **私有总控蓝图**：完整因果、反转、结局、各章功能和揭示时点。只供编译与审核。
2. **公开稳定契约**：人称、视角、叙述时点、题材现实层级、叙述声音、语言呼吸、标题承诺，以及开篇前已经成立且不会泄露答案的事实。

不得把人物秘密、伏笔真义、完整反转顺序、后章结论写进公开稳定契约。

公开稳定契约同时维护**公开身份名册**：正文中已经可以公开使用的人名、性别称谓或代词、人物之间的公开关系，以及他人自然称呼主角的方式。第一人称正文可以用“我”描述主角，但记者、亲友、校方、文件或第三方对白需要称名时，执行包必须提供正确姓名，不能让正文模型自行发明。秘密身份、隐藏关系和后文才揭示的称谓不得进入名册。

同时建立私有**硬事实保真表**。只记录改变后会损伤主线、人物选择、证据强度、时序或现实机制的事实，并拆出：

- 实体与关系；
- 数量、范围和“完全/部分/近似”等精确度；
- 肯定、否定与尚未确认；
- 行为或传递方向；
- 发生、获知与叙述时点；
- 原因、结果和确定性。

保真表不是原文句子摘录，而是不可弱化的语义约束。

### B. 编译下一章

输入：私有总控蓝图、目标章节、**初始化阶段冻结的公开稳定契约**、上一版已验收状态账本、必要时上一章结尾的最短承接片段；有参考文本时还包括通过验证的章节边界 map。

公开稳定契约是每一章都必须显式传入的独立上游产物，不得假设它仍隐含在完整蓝图、首章执行包或历史正文中。为隔离未来信息而只截取当前章节蓝图区段时，必须把公开稳定契约作为另一份无剧透输入同时交给编译器。缺少该产物，或其人称、视角、叙述时点、公开身份名册与当前章节区段冲突时，停止编译；不得让模型根据人物姓名、段落语气或上一章残留自行猜测。

按以下顺序工作：

1. 先加载公开稳定契约，再用边界 ID 锁定原标签、源范围、起止锚点、最后不可越过文本和下一章禁止提前出现文本；目标标题、源区段和功能终点必须一对一。未通过 `validate-boundaries`，或执行包“输出与章首”没有逐项兑现稳定契约时不编译。
2. 确定本章结束时读者和人物分别允许知道什么。
3. 给大纲信息分类：
   - **章首已成立**：可进入状态账本；
   - **本章必须建立**：可进入本章任务；
   - **本章只出现表象**：只写可观察表象，不写真实含义；
   - **本章之后才揭示**：完全省略，连“禁止猜某答案”也不写；
   - **纯写作约束**：可进入声音、节奏或篇幅要求。
4. 只保留完成本章因果、人物、情绪、关系、信息和承接所需内容。
   - 对每条跨章概述同时登记“允许抽象层级”和“场景所有章”。当前章只概述某个后续执行结果时，不携带该执行过程的动作顺序、对白、物件和反馈；事实在全篇真实也不能成为提前细写的理由。
   - 参考原文故意让冷开场概述、后章现场细写或先误记后校正时，分别保留各边界当下的表面表述。不得用后章更精确的现场事实覆盖前章原有叙述，也不得把前章概述扩写为后章现场。
5. 把必须细写的内容编译为少量有先后顺序的**场景功能单元**；把纯移动、程序或时间推进编译为轻过渡，不把所有节点强行写成对峙。
6. 完整硬事实保真表留在控制器私有审核层。正文可见的场景卡只引用事实 ID，并把该事实写成角色世界中的自然事实；每项事实只在一个最合适的场景卡中出现一次。
7. 生成一个独立的正文可见执行包。正文模型即使只看到这个文件，也能写完本章；但看不到完整审核表、攻击检查和后章答案。包内的人称、视角、叙述时点、公开称谓和叙述声音必须从公开稳定契约逐项下沉，不得被章节局部措辞或模型默认习惯覆盖。
8. 发布前做条款冲突预检：同一事实、判断或声音载体不能既被“必须保留/直接写出/指定载体”要求，又被留白逐字禁止。发现冲突先返修执行包，不得交给正文模型猜优先级。
   有参考原文时还要逐边界核对：章节局部事实、抽象层级和场景所有权必须与对应源范围一致；不能用全局保真表把有意保留的先验误记、概述或预叙统一成后文答案。
9. 逐项对账上一版账本中的活跃人物、持有物和未完成义务。每项只能明确选择：继续携带、在本章某个单元完成可见交接 / 归还 / 失效，或保持为不在场但仍活跃的状态；不得因为本章主线用不到就静默删除。人物在本章恢复行动自由、离家或转场时，优先检查其手机、钥匙、证件、衣物和随身物是否需要闭合。
10. 按单元顺序做一次包内连续性扫描：前一单元已经放下、交出、关闭、离场或失效的人物与物件，后一单元不得无交接恢复为手持、在场、开启或可用。章尾动作必须放在该对象最后一次使用之后。写作链不得保留“或者、二选一、由正文决定”等未编译分支；编译器必须选定一个可观察触发与一条确定链。
11. 当私有蓝图区段把账本中的“计划 / 将要 / 尚未完成”写成“已经交付 / 已出结果 / 已完成”时，以已通过账本为准。若本章需要完成该义务，必须在当前章某个单元中安排可见的动作—交接—结果桥，并在章首保持旧状态；不得把结果倒灌成章首事实，也不得用一句“此前已经”跳过责任链。
12. 对照普通事实和活跃状态做事件新旧扫描。已经成立的解约、延期、伤害、公开声明或关系终止不能再次作为本章首次到达的新打击；只有当前章明确授权了新的对象、强度、证据、风险或不可逆后果，才可作为后续变化再次出现，否则降为背景或退回私有蓝图。
13. 对集合对象做数量守恒扫描：总量、当前位置、保管者和已交出数量必须能同时成立。不得一面写“三份都在背包”，一面又写其中两份在外部机构；逻辑并列、同属证据链或同屏展示也不自动授权物理共址。
14. 实体与实体产生的记录分开做去向守恒：原件、残片、样本等实物已经销毁、遗失或交出时，不能同时声称该实物仍“入卷、在库、留底”；如果进入档案的是鉴定结论、照片、扫描件、会议记录或副本，必须使用对应对象名，不能用原实体代称。
14. 对机构行为做权限扫描。账本若记录工作室、公司、账号或职位已暂停、撤销或冻结，当前章不得再以该机构或身份发布、签署、调阅、收款或作证，除非本章先有可见恢复授权；可以由个人完成的动作必须明确改为个人主体。
15. 对未知身份和证据模态做降级扫描。未署名号码、匿名账号或遮蔽身份只允许保持未知；人物把它联想到某人时只能登记为推断。个人账号、非官方渠道、初步比对或阶段性结果不得在执行包中升级为官方、正式、最终或已证实结论。
16. 发布正文可见包前扫描章节 ID。包内不得出现任何序号大于当前章的 `Bxxx`，也不得用“下一章、后续揭示、未来答案”等说明复述私有蓝图；未来章节标识即使出现在禁写句里也属于泄漏。

编译时在内部为每个高权重场景功能单元确认：

- **起始状态**：进入单元时人物、关系、信息或风险处于什么状态；
- **触发 / 输入**：什么打破或推动该状态；
- **必须回应**：谁必须以动作、话语、判断或选择作出回应；
- **反馈 / 反作用**：对方、环境或新信息怎样使回应产生后果；
- **状态变化**：单元结束后，行动、关系、信息或读者压力具体改变了什么；
- **情绪 / 读者压力变化**：只有当前单元承担情绪任务时才写，说明压力从什么状态变到什么状态，以及通过何种人物行为、话语或感官变化落地；
- **展开等级**：细写、标准或轻过渡；
- **硬事实引用**：本单元必须保真的事实 ID。
- **保持不具体**：只列为了衔接当前单元、模型最可能擅自补出的发现方式、精确时长、传播渠道、证据来源或机制；不是穷举所有未知。

场景闭环不是要求解决悬念。悬疑单元可以只从“感觉异常”推进到“确认危险正在接近”；情感单元可以延期宣泄；喜剧单元可以用误解加深或笑点落地作为状态变化；氛围单元必须让感官变化持续改变判断或压力；轻过渡只完成时空、人物进退场和物件状态桥。

不要把一个动作拆成多个虚假单元，也不要把整章塞进一个单元。划分标准是：每当人物选择、关系、信息或读者压力发生一次不可忽略的变化，就结束当前单元。

不要把上述完整分析表原样交给正文模型。每个单元压缩成一张短执行卡，只保留：

1. `变化`：从什么状态推进到什么状态；
2. `写作链`：触发 → 必须回应 → 反馈；
3. `压力`：仅情绪或氛围任务需要；
4. `直接写出`：不可摘要的对白、动作或信息；
5. `留白`：用肯定句写正文只能停在哪个当前结果；不在正文可见包中逐项列举禁止出现的具体答案、物件或机制；
6. `保真`：硬事实 ID；
7. `展开`：细写、标准或轻过渡。

同一事实只保留一个可写位置：正文可见执行卡负责怎样发生，私有硬事实表负责语义核对，情绪压力直接压进相关执行卡。不要在任务、执行卡、篇幅、声音和事实预算中五次改写同一句话。

#### B1. 近通过执行包的定点返修

执行包已经通过章节身份、主要内容和稳定契约检查，只剩容量越界、单个对象状态冲突、控制 ID、局部留白泄漏或一两处授权污染时，不从完整蓝图区段重新抽样。给返修模型的输入只包含当前失败包、公开稳定契约和**无剧透返修单**；返修单写明冻结区、允许改动字段与可验证验收条件。未列入返修单的单元、事实、顺序、人称、声音和篇幅上限全部冻结。

定点返修不得接收参考原文、未来章节或私有攻击样例。修完后重新运行完整 packet 控制器；旧包与返修包分别保存为不可变尝试。若一次同模型定点返修仍失败，才按模型路由升级；连续修补仍扩大污染时退回 B 编译，不在坏包上无限叠改。

若两个独立生成尝试（不同模型，或同模型首稿与冻结范围返修）都完成全部场景功能，却稳定低于包的硬下限，而达到下限的版本依赖重复动作、同义确认或解释性补字，最早责任节点是容量预算。退回执行包，仅下调下限到原始授权容量的约 65%–75%，保留已经验证的上限与内容；不得继续要求正文为过线扩写无新反馈的文字。`4/5` 是控制器允许设置的下限上界，不是推荐把下限顶到该上界。

每个场景功能卡还要有自己的正向有限清单，并明确拆成“人物”“在场对象（对象@位置@可见/可触达状态）”“可用事实”。章节跨越时间、地点或独立场景时，后段才出现的人物、物件、称呼和结论只能进入对应后段卡，不能预先放进章首或前段卡。只在“可用事实”出现、未在“在场对象”登记的物件，不得被正文人物看见、触碰或移动。全章对象清单只能承载真正跨单元持续存在的共享状态，不能替代单元级清单；否则后场景对象会倒灌到前场景。

每个单元必须用一行且只用一行 `- 本单元正向有限清单：人物：……；在场对象：……；可用事实：……`。不得拆成三个普通项目，也不得用无标记的“人物 / 对象 / 事实”块替代。全章正向有限清单必须是各单元清单的必要共享子集或并集摘要，不能一边遗漏单元对象，一边用“可自由创造陈设、衣物、环境”等句子重新开放边界。

清单中的集合词默认保持集合粒度：“女性用品”“日用品”“衣物”“酒”只授权按该集合结果出现，不自动授权枚举牙刷、鞋、相框、酒杯、颜色、品牌或数量。只有具体子对象本身承担动作、证据或回收功能时，才把它单独登记。

编译每个写作链时同步做对象—动作核验：所有需要看见、触碰、打开、关闭、移动、翻找、展示、藏起、进入或离开的宾语，都要在当前单元“在场对象”中以同一实体登记。集合级结果和概述动作只授权集合词与概述谓词，不授权正文模型自行设计子对象、容器、子地点、路线、搜索顺序或工具。若具体实施过程并不承担功能，就让写作链保持概述；若承担功能，就在清单中明确登记，不能留给正文模型补全。

正文可见层只保留六类内容：

1. 输出身份与唯一一处篇幅目标；
2. 本章开场真正需要的时间、地点、在场人物和最短承接状态；
3. 本章唯一任务；
4. 少量按先后排列的场景功能卡；
5. 声音、语言呼吸和局部创造边界；
6. 章尾状态与用肯定句表述的当前知识停点。

完整 H 事实等价表、肯否与强弱核验、未来信息边界、攻击检查、场景覆盖矩阵和审计结论都属于控制器私有层，不得随正文执行包交给正文模型。场景卡可以保留 H ID 作为追踪引用，但自然事实本身必须在唯一可写位置完整出现，不能要求正文模型另查私有表。

具体攻击样例同样属于私有层。不要在正文可见包的否定句中罗列模型最可能乱补的物件、数字、来源或后文答案，这会把禁写内容变成最近语言样本。正文层改用“当前可用对象/事实只有……”的正向有限清单，或只写知识停点；私有层再用完整反例表审核。

正文可见包中的硬事实只使用控制器分配的短别名 `H-01`、`H-02`……，不得暴露私有蓝图中的人物、物件、信号或章节分类 ID。编译器可以输出内部 ID 供控制器核对，但正式写入正文输入前必须由控制器按首次出现顺序确定性改名；正文模型不需要知道内部分类名称。

执行包会成为正文模型最近的语言样本。场景单元中的可写内容使用角色世界里的自然肯定句；“方向不能写反、必须保留、不可弱化、不得新增”等命令式审核语言只放在控制器私有核对层。正文可见包的保真字段只列 H ID，不携带命令、攻击样例或未来答案。若某项内容尚未说明，写成当前世界事实，例如“她只说张远发现了，没有说明发现经过”，而不是留下需要模型自行补齐的因果空洞。

若本章存在点名、身份核验、公开报道、文件记录或第三方谈论主角的场景，把本章需要的公开姓名与称呼从身份名册带入执行包。不要因为正文采用第一人称就省略这些外部称谓。

篇幅预算只保留一个主要数值边界，固定使用阿拉伯数字 `下限–上限 汉字`，供运行器读取交付下限。句数、段落数、平均段长等改写成“短段为主、关键动作单独落段”之类定性呼吸要求，除非它们本身就是不可替代的成品格式。即使私有蓝图写了精确段数，编译器也必须翻译而不是复制。不要把多个相互牵制的精确数量同时交给正文模型。

篇幅范围必须由本章实际授权的执行卡反推。若提取或重构时删除、后移了参考文本中的动机、事例、评论或余波，必须同步降低本章篇幅预算；不得保留旧篇幅，再要求正文模型用未授权内容补齐。总字数只用于发现异常，不凌驾于场景闭环。

编译后再做一次“授权篇幅删除测试”：把参考原文中未进入执行卡的物件枚举、景物、重复解释、精确路线和旧对白措辞全部视为不可用，只估算剩余功能能承载的篇幅。若下限只有依赖这些已删除内容才能达到，先下调执行包预算，不能把矛盾留给正文模型。

编译器原始 packet 的每个场景单元必须使用九个以 `- ` 开头的 Markdown 项目行，并增加机器可读的私有容量载体：`- 授权容量载体：对白轮次 N；动作反馈闭环 N；认知或感知转折 N；事后反应 N`。只统计能在正文中独立展演、且已经由写作链、直接写出和正向有限清单授权的载体：一句问答算两个对白轮次；连续动作只有在产生可见反馈并改变后续反应时才算一个动作反馈闭环；同一结论的换句话说不重复计数；位置移动、证件核验、证据确认和结论落点不能因为箭头多就虚增容量；事后反应必须发生在主变化之后并承担余波。单元最多登记 8 个对白轮次、4 个动作反馈闭环、4 个认知或感知转折和 2 个事后反应，超过时必须拆分单元或回查是否重复计数。控制器验收后把计数写入自己的 sidecar，并从交给正文模型的 Markdown 中剥离该行。

正式接收新版正文包时，控制器用容量载体复算两道门：目标下限不得高于安全承载值，目标上限不得高于授权绝对上限。五个执行字段的汉字量只用于发现编译器是否靠写长控制说明抬预算，不能直接充当正文容量。缺少容量载体、字段超长、计数越界或任一道容量门失败时，packet 必须判为 blocked；不能只把上限略微调低后保留仍会制造补字压力的旧下限。

不要用模糊占位句替代必要节点。若本章必须揭示某个答案，就明确写入“本章必须建立”；若不该揭示，就从执行包中完全删除。

不要为了压缩而改变语义算子：

- “相同”不能改成“相近”，“全部”不能改成“部分”；
- “没有发现”不能改成“已经排除”，“尚未确认”不能改成“确定”；
- “先发生 A 再发生 B”不能合并成不分先后的结果；
- “A 传给 B”不能只写成“两者有关”；
- 明确数字可以按任务要求保留或宽化，但宽化后不能改变证据强度和因果。

编译后把执行包的硬事实逐项回对私有保真表。要求语义等值，不以“整体意思差不多”通过。

### 执行包的人称对齐

执行包会成为正文模型最近的语言样本，不只是语义数据。除“人称契约”一行外，状态、因果、情绪、篇幅和章尾字段也必须使用与目标正文一致的称谓。

- 第一人称正文：用“我”描述叙述者的经历、感知、判断和动作；需要区分角色职责时用“叙述者”，不要在几十条节点中反复用主角姓名或“他”。
- 第三人称正文：按既定主角姓名或代词描述，不混入第一人称。
- 多视角正文：每个视角单元单独标明称谓，切换边界之外不混用。
- 对白中的称呼、他人对主角的指代和角色名单不受此限制。

交付前扫描执行包：如果正文照抄其中的主角称谓会导致人称错误，先改包，不要指望正文模型用顶部一条规则自行抵消。

同时反向扫描：若本章他人必须点名或核验身份，而执行包没有提供主角的公开姓名、代词或关系称呼，先补入公开身份名册，禁止正文模型用占位名或自造姓名填空。

若本章会触发回忆、前世、闪回、遗物回扣或跨时间对照，执行包必须补一个最小的**历史连续性边界**：只列本章可调用的既有事件、当时仍存活且可在场的人物、已经出现的物件，以及不可颠倒的死亡或离场顺序。不要只写“回忆过去”，否则正文模型会用新物件和新场面填空。

### C. 审核章节

输入：私有总控蓝图、发给正文模型的执行包、待审正文、当前状态账本。

逐项检查：

- 本章必要功能和因果节点是否完整；
- 本章是否在正确的抽象层级兑现重点：概述有没有被扩成别章场景，细写有没有被压成一句结果，章内真实信息有没有抢占其他章节的唯一兑现位置；
- 本章硬事实的数量、范围、极性、方向、时点和确定性是否等值；
- 是否出现执行包没有授权的新身份、前史、地点、数字、动机、证据、规则、长期状态或结论；
- 是否泄露本章揭示边界之后的信息；
- 人物知识、读者知识、时间、位置、物件、关系和未完成动作是否连续；
- 每个带对象的动作是否存在明确且合理的“谁—对什么—做什么”；物件从原位置到新位置是否有可见移动，替换物与旧物的安装、拆除或交接顺序是否成立；
- 感官证据是否只支持正文声称的确定性：没听见明显动静不能写成确认无人、没有呼吸或没有危险，局部观察不能升级成幕后目的与全局结论；
- 人物的点头、停顿、残句、避视或第三方转述是否只支持其表面事实；叙述者据此作出的出轨、设局、动机或关系判断必须保持为该人物的推断，不能被审核报告和账本升级成客观确认；
- 上章离场、外出、住院、失联或仍在当前场所的人物，本章首次出现前是否有最短且可见的离场或返场桥；
- 回忆、闪回或双时间线是否只调用已有事实，人物存亡与事件先后是否成立；
- 情绪是否经过刺激、克制或阻滞、外化、宣泄或有依据的延期、余波；
- 对话是否兑现该说出口的身份、权力、判断与情绪功能；
- 每个高权重场景单元是否从触发推进到指定状态变化，而非只提到节点；
- 承担情绪任务的场景单元是否同时完成规定的情绪或读者压力变化，而非只有事实结论；
- 篇幅是否只补足未完成的场景闭环，而非靠无关细节凑长；
- 每个自创细节删除后，是否会改变当前动作、关系、信息判断、读者压力、人物声音或必要方位；若均不改变，即使局部闭合也应删除；
- 同一主题的重复是否每次改变对象、强度、证据、关系、风险或不可逆后果；
- 句子和段落是否符合执行包的语言呼吸。
- 正文是否泄露“硬事实、冻结项、必须节点、同义煽情、保持连续、任务”等执行包或返修单的控制措辞。
- 正文是否把“不能写反、不可弱化、未授权、保持不具体”等保真命令加工成人物对白或叙述判断。

审核必须产生两张内部表，再下结论：

1. **场景单元完成矩阵**
   - 逐单元检查变化、写作链、压力、直接写出、留白、保真和章尾状态；
   - 每项标为完成、缺失、改写或越界，并引用正文中的可见证据；
   - 一个事实被提到但没有产生执行卡规定的反馈或状态变化，仍记为缺失。
2. **段落功能归属表**
   - 每个非空正文段只可归入：某个单元动作、某项硬事实、压力变化、人物特有声音、必要时空 / 进退场桥；
   - 若无法归属，或删除后下一动作、关系、信息判断、读者压力、人物声音和必要交接均不改变，标为无功能；
   - 对白已经成立后，旁白只用抽象语句重复其含义，默认标为同义解释；除非该判断属于叙述者特有声音，并改变下一反应或读者压力；
   - 氛围段若持续改变危险判断、喜剧预期或情绪压力，可以保留；只有画面而没有变化时删除。

两张表之外必须执行一次**授权溯源扫描**。扫描正文中新出现的具体身份、物件、地点或路线、时间或数字、外貌或动作、前史或习惯、原因或动机、知识结论和跨章连续状态；逐项寻找执行包场景卡、正向有限清单、H ID、章首状态或账本来源。“现实中常见”“让场景更自然”“局部闭合”不能单独充当授权来源。找不到来源时，标记为删除、返修或降级，并同时追踪依赖该新增内容成立的派生句。

对白、名词修饰语和抽象关系也要按事实审核，不能作为漏检通道。角色被授权“解释数据”，不等于授权他说数据可调阅、已经随身带来、来自某份正式记录，或承诺新的制度动作；这些话会建立访问机制、对象持有或后续义务。正文把“留存的话术”写成“上级下发、公司统一发布”时，修饰语已经新增来源和传播事实。执行包只授权“同属一条证据链、并列材料、关联记录”时，不得自动放行“同一袋、同一容器、同一文件夹、同一目录”等具体共址关系；共址必须有对象、介质和位置的明确授权。

正向有限清单是闭集，不是例子。门、房间或某个概述动作不自动授权钥匙、门卡、容器、工具、相邻走廊、前室、楼层和实施步骤；“开门必然需要”“自然公共区域”“为了连贯”都不是来源。带中文引号写在“直接写出”中的锁定台词必须逐字核验，不能用近义改写、代词替换或拆句冒充。当前拒绝、未知和尚未开始也不得被审核放行成“永远、再也、绝不会”或已经完成的新决定。

另外扫描语言表面异常：非既定的中外文混写、机械字段口吻、主谓宾对象错位、物件位置瞬移、安装 / 拆除顺序矛盾、感官证据越级、设备或动作不可能、引号和章节格式失守。表面异常不能以“有功能”通过。

审核输出必须立即从 `# 第 N 章审核` 开始，不写 Skill 简介、文件说明、路径引用或架构建议。必须依次包含：

1. 结论；
2. 场景单元完成矩阵；
3. 段落功能归属表；
4. 当前章问题；
5. 安全返修单。

缺少任一部分，审核输出本身判为无效。段落功能归属表可以把功能完全相同的连续短段合并定位，但所有拟删除、替换或补写的文字必须单独列出，不能只写“整体精简”。

审核顺序固定为：

`本章 P0 与章节所有权 → 硬事实与知识边界 → 单元完成矩阵 → 段落功能归属 → 人物与物件连续状态 → 感官证据确定性 → 语言表面 → 篇幅`

P0 关键词命中不等于通过。若当前章把别章拥有的执行过程提前写完，或把本章要求细写的高权重变化压成关键词清单，`核心目的` 和对应 P0 都必须判为返修。

篇幅最后检查。所有执行卡已经完成时，不因低于参考旧长度要求自由扩写；只有矩阵存在功能缺口时，才允许增加文字。

审核结论只能是：

- `通过`：允许更新账本；
- `返修`：正文不得进入账本，先生成安全返修单。

自动化审核除上述人读报告外，还必须输出 `audit-result.schema.json` 对应的 JSON sidecar。程序只接受 sidecar 中的 `operation`、章节边界签名、`verdict`、缺失单元、越界事实、返修范围和检查项与 Markdown 一致的结果；不接受退出码或正文里的“通过”作为状态。

布尔检查不能代替证据。自动化审核还必须输出 `draft-audit-evidence.schema.json` 对应的证据 sidecar：

- 每个标准或高权重单元分别引用正文中真实存在的触发、回应、反馈和新状态文字；
- 四槽是功能角色而非四句配额：已经发生并建立不可逆状态的公开动作，可以由同一条精确证据同时承担回应与新状态；不得为了填槽强迫正文追加“已经不可逆、收不回了”一类解释句；
- 执行包中的“只给、只留、最短、到此为止”属于封闭边界。指定反应之后追加的比喻、环境投影、解释或第二层感受，必须作为独立授权项核验，不能用“等效感知”放行；
- 兼容旧执行包时若条款冲突，按“硬事实及必须保留/直接写出 > 指定压力或声音载体 > 一般留白 > 自由创造”裁决。低优先级留白只能限制扩写和客观化，不能删除高优先级明确要求；新编译执行包不得依赖这条兼容规则，必须在发布前消除矛盾；
- “直接写出”默认核验语义动作或事实是否可见，只有带引号的指定对白、固定硬事实句或明确标记逐字时才做字面匹配。审计结果若已为某直接写出项提供有效证据，不得再以该项未逐字出现为由判同一单元缺失；
- 轻过渡至少引用触发和完成后的状态桥；
- 每个非空正文段以序号与文本哈希逐段归属，不能合并后留下覆盖缺口；
- 每项“直接写出”引用正文原句；
- `authorization_findings` 逐项保存疑似新增内容的正文原句、类别、授权来源、判定和理由；声称 `authorized` 时至少提供一个来源引用，判为 `delete`、`repair` 或 `downgrade` 的项目不得在 `--require-pass` 下通过；
- 证据引用必须是正文真实子串，正文哈希与汉字数必须可复算。

进入账本前运行 `controller_artifact.py validate-draft-audit --draft ... --evidence ... --require-pass`。任一场景状态不是 `complete`、任一段仍标为 `delete/repair`、任一授权项仍需删除 / 返修 / 降级、证据不存在、段落漏覆盖或哈希不一致时，不得声称通过。

当审核证据显示所有单元完整，且剩余问题全是正文中唯一出现的精确 `delete` 引文时，优先运行 `controller_artifact.py apply-audit-deletions --draft ... --evidence ... --output ...`。控制器只允许保留段、能被这些精确删除引文完全解释的待修段，或正文段内容与唯一删除引文完全相等的整段删除；随后删除引文并收拢由删除产生的相邻标点，不让模型借返修机会重写整段。存在缺失单元、无法由精确引文解释的整段删除或非删除型问题时该命令拒绝执行。

审核模型不负责计算哈希和汉字数，也不自由抄写正文。自动化调用时先由控制器生成带 `Pxxx-Sxxx` 句子 ID 的 audit view，再让审核模型输出符合 `draft-audit-semantics.schema.json` 的语义 JSON：逐单元句子 ID 证据、逐段归属与判定、直接写出句子 ID 和授权发现句子 ID。随后必须运行 `controller_artifact.py accept-draft-audit-semantics --draft ... --raw ... --packet-sidecar ... --output ...`，由控制器把 ID 还原为冻结原句、补入章节身份、正文哈希、段落哈希和汉字数，并再次验证。未经过这一接收步骤的模型自报审核不能进入返修或账本。

审核与账本语义 JSON 的字符串值内部不要嵌入英文双引号。需要在 `reason`、`source_refs` 或状态文本里提到台词时，使用无引号概述或中文标记；正文原句本身只通过句子 ID 交给控制器恢复。解析失败的 JSON 必须作为独立失败尝试封存，不得手工补转义后冒充模型直出通过。

审计前先运行 `controller_artifact.py build-audit-view --draft ... --output ...`，把控制器编号后的全文段落清单与当前正文一起交给审核模型。审核模型必须逐项复制清单中的 `index`，输出的 `paragraphs` 数量必须等于 `paragraph_count`；不得自行合并相邻段落或重新编号。

若 `--require-pass` 已确认所有单元完整、所有段落保留且所有授权项解决，但洁净稿仍低于 packet 下限，不再返修正文。运行 `controller_artifact.py recommend-length-range --draft ... --evidence ... --packet ... --output ...`：控制器以实测洁净稿给出约 `90%–120%` 的新范围建议，退回 packet 编译端重建容量 sidecar。该建议只在完整 audit pass 后产生；存在任何功能缺项或授权问题时不得用降预算掩盖。

### D. 更新状态账本

只从**已通过的正文**提取事实。大纲写了但正文没写出的计划，不得进入账本。

自动化更新必须同时提供同章、已通过 schema 且 `verdict=pass` 的 audit sidecar。缺少该前置证据、章节边界签名不一致或 audit 仍需返修时，不得生成可进入下一章的正式账本。

账本中的身份与确定性不得高于正文：匿名发送者保持未知，人物联想进入 `narrator_inferences` 而不是普通事实；个人账号、非官方或初步结果保留原模态。正文没有明确具体时间或地点时，分别使用“正文未明确具体时间”“正文未明确具体地点”，不得从“手机亮起、关上屏幕、很快、已经发出”等动作或相对词推断室内、当天或具体时段。证据只写“因观察期暂停”时，不得补成“观察期未结束”等正文没有出现的负面状态。

更新：

- **普通已成立事实**：事件、知识与公开结果，可在不改变语义时压缩；
- **当前活跃状态**：人物在离场、地点、持有物、伤情、关系、程序、延期情绪和未完成动作；
- **跨章未完成义务**：承诺、必须返场、必须归还或处理的物件、必须承接的动作与程序；
- **待回收信号**：正文已建立但尚未完成表层回报的异常、问题或伏笔；
- **已闭合项**：从哪一类、哪个稳定 ID 退出，在当前哪一章因何可见事件而完成、失效或回收。

活跃状态、未完成义务和待回收信号都使用稳定 ID。上一版中的这些项目，在下一版只能：

1. 以同一 ID 留在同一活跃分区；
2. 进入“已闭合项”，写明 `completed / invalidated / paid_off`、闭合章节、可见事件与证据。

不得改名、换区或静默删除。自动化时不要让账本模型重写完整状态：先给正文生成句子 ID view，让模型只输出符合 `ledger-semantics.schema.json` 的增量语义；上一账本的每个活跃 ID 必须且只能提交一次 `carry / confirm / revise / close`。再运行 `controller_artifact.py accept-ledger-semantics --draft ... --audit ... --previous ... --raw ... --markdown-out ... --sidecar-out ...`，由控制器继承旧事实、恢复冻结原句、生成闭合记录和确定性 Markdown。声音锚点由模型选择且只能选择一个正文句子 ID，锚点文本由控制器按该 ID 回填完整原句（包含标点）；不得为了补标点让模型重写整份账本 JSON。新事实、新活跃项及闭合证据只能引用当前正文句子 ID；上下文可以引用当前句子 ID 或上一账本稳定 ID。控制器拒绝漏项、重复操作、carry 偷改、无当前证据的新状态、跨区移动和错误闭合类型。

生成账本后还必须用 `controller_artifact.py validate-ledger-state --previous ... --current ...` 做前后差异检查；第一章没有旧账本时只校验当前状态。全文结束后再做前向连续性与反向回收审计。模型提交的原始语义、控制器输出和失败记录都要保留为不可变尝试，只有通过控制器和总控批准的账本才能成为下一章父产物。

账本定点返修必须在返修单首部加入唯一机器权限声明：`<!-- allowed-json-paths: ["$.路径", "$.数组[id=稳定ID].字段"] -->`。路径声明使用 JSON 数组；非 ID 数组只能授权到整个数组。返修后先运行 `controller_artifact.py validate-ledger-repair-scope --before ... --after ... --memo ...`，再接收账本语义。任何未列路径的改动即使内容方向正确也属于越权，整次尝试拒绝；缺少权限声明、没有实际变化或重复声明同样 fail-closed。

不要把“后面会发生什么”写入状态账本。

## 信息隔离硬规则

正文模型只能收到：

1. `zhihu-salt-chapter-drafter`；
2. 当前章节执行包；
3. 可选的当前章旧稿与安全返修单。

正文模型不得收到：

- 完整大纲或未来章节大纲；
- 私有总控蓝图；
- 完整反转表、结局解释或伏笔真义；
- 全部历史正文；
- 审核端包含后文答案的分析；
- 未验收章节及其派生状态。

自动化运行若使用禁读工具的隔离代理，不得再依赖要求代理自行读取的 `--file` 附件。应由运行器先在可信控制端读取并仅内嵌当前节点获准输入；JSON 可确定性压缩，参考原文、完整蓝图和未来章节不进入模型提示。主机记录中的模型名是请求路由，不得仅凭配置文件、自报文本或退出码宣称实际模型和产物已通过；仍须保存事件流、耗时、成本和控制器结果。

上一章正文若需承接，只放入执行包里的最短结尾片段；长期信息压缩进状态账本。

## 安全返修单

返修单只描述当前章节表面上需要删除、补足或改正的内容，不解释它为何会破坏未来设计。

总控端先在外部完成汉字数、段落数、节点数和事实项测量，再决定返修范围。不要要求正文模型逐字计数、逐段编号或输出计算过程；数字只作为验收边界，正文模型只执行明确的增删改任务。

返修单必须给出**改动预算**：

- `整章返修`：只用于核心因果、视角或结构整体失效；
- `区块返修`：明确允许重写的场景或功能单元，其余部分冻结；
- `定点返修`：列出要删除、替换、移位或补足的句段，其余文字冻结。

旧稿已经接近通过时，默认使用定点返修。不得用“润色全文”“适当扩写”“控制在目标字数”这类无边界指令触发整章重写。若需要补足篇幅，返修单要指出可以展开的既有场景单元、缺失的是触发、回应、反馈、状态变化、情绪阻滞还是余波，并给出大致增量；不得让模型靠背景、景物、回忆或新事实自行补齐。

定点返修单必须从两张审核表直接生成：

- 无功能段：引用最短可定位原句，指令为删除；不要用“精简一些”。
- 同义解释：说明它重复了哪句已经成立的动作或对白，删除或替换为缺失的反作用，不做换词润色。
- 缺失闭环：点名 U 编号与缺失格，只补该格。
- 未授权事实：点名具体事实及其派生句，一并删除；若连接仍需要，用“保持不具体”的既有结果承接。
- 授权溯源项：直接沿用证据 sidecar 中的正文定位、类别和来源缺口；不能只写“减少细节”，也不能删除后换成另一个没有来源的具体细节。
- 表面异常：给出明确替换目标，不借机重写邻近合格文字。
- 未列入改动预算的段落全部冻结。

安全写法：

- “删去本章输入未授权的录取原因推断。”
- “补足司机从拦车到动手的动作因果。”
- “父亲的态度变化尚无本章依据，恢复为账本中的既有状态。”

禁止写法：

- 直接告诉正文模型真正录取原因；
- 列出未来谁是幕后人、伏笔真实含义或最终结局；
- 用“为第七章反转做准备”之类创作结构标签解释人物生活。

## 失败优先级

以下任一项成立即返修，不用靠文笔优点抵消：

1. 提前泄露后章答案；
2. 漏掉或改写本章核心因果；
3. 弱化、加强或反转本章硬事实；
4. 新造会影响后文的全局事实；
5. 继承未在已验收正文中成立的状态；
6. 视角、知识或现实机制不成立；
7. 高权重场景只被提到，没有完成指定状态变化，或关键情绪与对话链被摘要掉。
8. 回忆或跨时间场景违反人物存亡、事件先后或既有物件来源；
9. 控制端审核措辞作为元话语泄露进正文。

轻微措辞、局部节奏和篇幅偏差在硬错误清零后处理。

## 工作流

1. 有参考原文时先机械提取并验证章节边界 map。
2. 初始化私有总控蓝图与公开稳定契约，并校验蓝图章节与边界 map 一一对应。
3. 从空账本或上一章已验收账本编译第 N 章执行包。自动化生产中，模型只交付 packet Markdown；章节身份、边界签名、哈希与结构检查 sidecar 由控制器在 Markdown 验证后生成，禁止把这些确定性 JSON 字段继续交给语言模型拼写。该规则不适用于 audit 与 ledger 的语义 verdict。
   - 自动化编译时，完整账本必须留在控制器侧；交给语言模型的是确定性投影的最小账本视图：保留普通事实、活跃状态、开放义务、待兑现信号和已关闭项的当前语义字段，删除重复的正文证据。不得为了省上下文删除关闭结果或把模型改成账本筛选器。
4. 让正文模型仅凭执行包写第 N 章。
5. 用完整蓝图按“硬事实 → 场景闭环 → 情绪压力 → 细节准入 → 语言呼吸”的顺序审核，但只给正文模型安全返修单。
6. 按最小改动预算返修；每次返修后重新审核全部硬事实和顺序，而非只检查被点名处。
7. 从通过稿更新状态账本。
8. 再编译第 N+1 章。
9. 全文完成后，在总控端做一次前向状态审计和反向回收审计；不要把完整全文重新交给单章正文模型扩写。
10. 前向审计必须逐章核对人物位置、物件持有者、电话 / 证件 / 钥匙 / 衣物等交接、未完成动作和知识确定性；反向审计从终章倒查每个活跃 ID 是否已闭合。单章全部通过但仍有悬空物件或静默消失状态时，全文不得进入最终交付。

## 输出边界

- 编译任务：只输出一个章节执行包。
- 审核任务：输出结论、当前章问题和安全返修单。
- 更新任务：只输出新状态账本。
- 不在这些输出里夹带完整大纲、私有推理或未来答案。
- 普通交互任务保持上述 Markdown 边界；自动化生产中的 packet 由模型输出单 Markdown 信封并由控制器生成确定性 sidecar，audit 与 ledger 仍输出 Markdown 和操作专属 JSON sidecar。只有接收脚本校验成功后的拆分文件才是正式产物。
